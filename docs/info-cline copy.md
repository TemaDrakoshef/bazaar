## Контекст проекта
- Репозиторий: https://github.com/TemaDrakoshef/bazaar/tree/main
- Язык: Python (FastAPI), grpc - межсервисное общение
- Брокер: Kafka и Rabbitmq - в будущем
- База данных: PostgreSQL
- Сейчас используется Docker Compose с несколькими сервисами (api-gateway, auth-service, catalog-service, etc.)
- В будущем — Kubernetes (возможно, с Kustomize или Helm).

## Цель
Настроить observability-стек, который будет включать:
- Сбор метрик (Prometheus, возможно, с экспортерами для Kafka/rabbitmq и PostgreSQL).
- Сбор логов (Loki).
- Сбор трейсов (Tempo).
- Визуализацию (Grafana с дашбордами).
- Алертинг (Alertmanager).
- Единый агент сбора телеметрии (OpenTelemetry Collector).

Всё должно быть развёрнуто локально через Docker Compose, но конфигурации должны быть готовы к переносу в Kubernetes (структура папок как в описании выше: infrastructure/ с подпапками docker/, kubernetes/, observability/, scripts/ и т.д.).

## Требования к решению
1. Все компоненты должны запускаться из docker-compose.yml (размещённого в infrastructure/docker/compose/).
2. Приложения (микросервисы) должны быть инструментированы OpenTelemetry (Python SDK) для генерации трасс, метрик и структурированных логов (JSON).
3. Должна быть настроена корреляция между логами, метриками и трейсами (через trace_id, span_id).
4. Дашборды Grafana должны показывать ключевые метрики (запросы, ошибки, задержки, загрузка БД, Kafka lag и т.д.).
5. Алерты должны быть настроены для критических событий (высокая задержка, падение сервиса, ошибки 5xx).
6. Конфигурации должны быть параметризованы через переменные окружения (для разных окружений).
7. В коде приложений должны быть добавлены необходимые зависимости и middleware.
8. Должна быть документация (README) по запуску и использованию стека.
